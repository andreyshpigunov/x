# Библиотека X

Помогай использовать X в выбранном пользователем шаблоне. X — необязательная библиотека интерфейса, а не обязательная основа каждого сайта на next-cms.

## Выбрать подходящий режим

- **Готовая сторонняя вёрстка:** сохраняй её дизайн, reset, сетку и рабочие компоненты. Подключай X только для нужной функции. Если задача решается существующим компонентом, не добавляй X ради единообразия.
- **React / Next.js / публичный шаблон next-cms:** используй `@andreyshpigunov/x/react`. Поддерживаются React **19** и React DOM **19**. Не расширяй поддержку до React 18 и не обновляй старый сайт до 19 без задачи на миграцию.
- **Обычный HTML/JS-сайт:** сохраняй vanilla API и атрибуты `x-*`. Не устанавливай React ради X. Продолжай существующий способ подключения и инициализации.
- **Изменение самой библиотеки:** сохраняй оба режима независимыми. Читай [проверки и разработку](references/development.md).

## Справочники по задаче

- Вёрстка, адаптивность, выбор utility-классов и каскад: [CSS-система](references/css.md); точные настройки и defaults: [индекс CSS-переменных](references/css-variables.md).
- Обычный HTML/JS: [vanilla API](references/vanilla.md), включая настройки, события, callback-сигнатуры, преобразования DOM и повторную инициализацию.
- Вспомогательные JS-функции, формы, типографика и выбор между X и браузерным API: [JavaScript](references/javascript.md).
- React: [примеры и особенности](references/react.md) и [полный контракт props/callbacks](references/react-api.md).

Читай нужный справочник до написания интеграции. Сигнатуры callback, аргументы, возвращаемое значение, async-ожидание, момент вызова и очистку проверяй отдельно: vanilla и React не взаимозаменяемы. Не придумывай onSuccess/onError/onChange там, где есть только DOM-событие или вообще нет hook. Приватные методы с `_` не используй как публичный API.

В vanilla `x-modal="name"` создаёт новый `#name` и удаляет исходник; селекторы, обработчики и наследование CSS планируй по конечному DOM. Vanilla slider переносит исходные узлы во wrapper, сохраняя обработчики; destroy возвращает те же узлы. Другие преобразования (lazyload, loadmore, dropdown) описаны в vanilla-справочнике. Повторный x.init() не сканирует страницу заново; x.destroy() очищает модули и разрешает новый x.init().

Справочники соответствуют исходникам 0.6.0-beta.1. При иной установленной версии сверяй реализацию; старые комментарии/cheatsheet могут расходиться с ней. Не переносить диапазоны классов и defaults по аналогии.

## Установленная версия — источник истины

До добавления импортов проверь package.json и lockfile потребителя, exports установленного X и его `dist/react/index.d.ts`. При работе в исходниках читай `src/react/index.d.ts` и `docs/react.md`.

React-адаптер разрабатывался как локальная предварительная версия. Номер старого npm-релиза сам по себе не доказывает наличие `/react` и `/styles/*.css`. Не подменяй проверку экспортов установкой `latest`. Для локального подключения используй проверенный `.tgz`; процедуру смотри в [разработке](references/development.md). Доступность новых API в опубликованном пакете проверяется отдельно, когда задача требует публикации или установки из реестра.

## Подключение в React

Читайте [контракты и примеры](references/react.md) при добавлении компонентов. Подключай только CSS нужных компонентов:

```tsx
import '@andreyshpigunov/x/styles/modal.css';
import '@andreyshpigunov/x/styles/dropdown.css'; // также Autocomplete
import '@andreyshpigunov/x/styles/sheets.css';
import '@andreyshpigunov/x/styles/slider.css';
```

В Next.js размещай эти импорты в соответствующем layout публичного шаблона или в принятой проектом точке входа стилей. Не делай весь layout клиентским: состояние, callbacks и хуки выноси в небольшой компонент с `'use client'`.

- Не вызывай `x.init()`, глобальные `init/destroy` или `typograf.live()` над React-разметкой. Они обходят/изменяют DOM вне React. Не добавляй `x-*`-атрибуты как замену React props.
- В React-интеграции не импортируй корень `@andreyshpigunov/x` ради компонентов: он включает vanilla X с браузерными глобальными объектами. Используй `/react`.
- Полный `x.css` содержит глобальный reset. Подключай его только когда шаблон действительно использует полную CSS-систему X; для готовой вёрстки достаточно отдельных стилей.
- SSR-контент страницы сохраняй вне модалки: `Modal` создаёт портал только после монтирования. Подгрузка и анимации не должны быть единственным способом показать основной текст страницы.

## Сохранить визуал

Перенос в React не означает редизайн X. Используй штатную структуру компонентов и существующие переменные `--modal-*`, `--dropdown-*`, `--slider-*`; задавай стили шаблона через `style`, `className` и предусмотренные props.

В X rem-масштаб обычно соответствует 10 px при стандартных настройках браузера. Изолированные React-стили **не меняют** корневой шрифт сайта. Если готовый сайт использует другой rem-масштаб, настрой нужные переменные в px/rem под его дизайн; не меняй `html { font-size }` ради одного компонента.

`Modal` портируется в body: переменные на обёртке страницы не наследуются автоматически. Передавай их через `style` модалки или класс её корня. Сохраняй анимацию закрытия и рейку sticky-крестика; не заменяй их отдельным fixed-крестиком или мгновенным размонтированием ради удобства реализации.

## Граница next-cms

X используется по выбору в публичном шаблоне. Сохраняй штатные модели данных, редакторы, формы админки, медиакомпоненты Picture/next/image и типографику CMS. Не заменяй их аналогами X автоматически. Если задача затрагивает схемы или админку next-cms, следуй инструкциям этого проекта; данный скилл их не переопределяет.

Для обычных полей React используй value/checked/onChange/onSubmit. Отдельного React-компонента Form или Typograf в X нет. Не придумывай отсутствующие экспорты и не вставляй результат обработки HTML как доверенный контент без требований самого проекта.

## Проверить результат

Выбирай проверки по изменённому поведению: сборка и типы потребителя, SSR/hydration, клавиатура и возврат фокуса, повторное открытие, независимые экземпляры, отмена устаревших запросов и очистка при смене страницы. Для визуальных изменений сравнивай со штатной X при одинаковом rem-масштабе и переменных. Для слайдера проверяй реальную последовательность touch-событий, а не только программный вызов pointerup.

Разделяй в отчёте пройденные автотесты, ручную проверку и оставшиеся ограничения. Создание кода или скилла само по себе не является публикацией релиза.
