# Изменения X и локальная проверка

Находи репозиторий по package.json с name `@andreyshpigunov/x`; не полагайся на абсолютный путь компьютера автора.

## Где менять

- `src/react/` — React-реализация, изолированный CSS и `index.d.ts`.
- `src/components/x/` — исходная vanilla-реализация и визуальный эталон.
- `scripts/build-react.mjs` — формирование dist/react и dist/styles; не правь только dist.
- `package.json` — доступные exports, optional peerDependencies React/React DOM 19.
- `test/fixtures/react-next/` — исходники стенда; `.local/react-test/` — генерируемая копия.
- `docs/react.md` — полные контракты и локальное подключение.
- `skills/x-library/` — версия этого скилла, сопровождаемая вместе с библиотекой.

Сохраняй vanilla exports и работу без установки React. React не включается в браузерный vanilla bundle; React-вход сохраняет `'use client'`. У адаптеров собственные классы, чтобы глобальные обработчики старой X не управляли React-элементами. Содержимое принадлежит React: не клонируй его через innerHTML и не перестраивай императивно.

Сопоставляй не только внешний вид, но и жизненный цикл: Strict Mode, прерванные анимации, отмена запросов, вложенность, удаление компонента и переходы страниц. Не копируй глобальную архитектуру vanilla там, где нужны локальные состояния и callbacks React.

## Проверки и архив

В репозитории X:

```sh
npm test
npm run test:react
```

Вторая команда собирает пакет, создаёт npm-архив, устанавливает его в изолированный Next.js-стенд, проверяет vanilla-потребителя без React и запускает браузерные проверки Chromium/WebKit. Она пересоздаёт `.local/react-test/app/.next`: сначала останови запущенный dev:react этого же стенда. Не останавливай посторонние серверы.

```sh
npm run dev:react
```

Печатает URL стенда и путь к `.tgz` с хешем содержимого. Страницы `/` и `/components`. После изменения исходников пакета перезапусти команду: node_modules здесь намеренно установлен из архива, не из симлинка. `X_NPM_OFFLINE=1` применим, только если зависимости уже есть в кеше.

Устанавливай показанный архив в выбранный пользователем тестовый сайт командой `npm install --save-exact /actual/path/to/archive.tgz`. После установки проверь exports и сборку потребителя. Не угадывай путь или хеш. Если используешь npm pack отдельно, сначала собери пакет: prepublishOnly не гарантирует сборку при pack. У разных локальных архивов одной версии должны быть разные имена, иначе возможен старый npm-кеш.

Для этой предварительной версии работа ведётся локально. Наличие подготовленных файлов не означает, что React-экспорты уже есть в реестре. Релиз, push и publish выполняются только в рамках отдельной задачи на выпуск; скилл не запускает их автоматически.

При изменении API обновляй типы, docs/react.md и соответствующие примеры скилла. Не добавляй обходные правила в скилл вместо исправления подтверждённого дефекта библиотеки.
